# Sdui Meet moved into the monorepo, and the extra login check now asks once a day instead of every six hours

*Sdui app news for November 2026 (2026-11-01 to 2026-11-27).*

**In 30 seconds**
- **Act:** send changes to Sdui Meet and vault-proxy to the monorepo, not the old repos. If you call the Sdui API,
  check the three API changes below.
- **Coming:** a portal for school operators, step-up without 2FA, and the Untis connection moving in.
- **Win:** encrypted push on iOS, an Android keyboard fix, faster unread counts; on-device translation is ready.

The *monorepo* is [sdui-monorepo](https://github.com/7education/sdui-monorepo), the one GitHub repo where all Sdui
code is being collected: the app (iOS, Android, web), *Core* (the backend behind the `/v1` API) and the timetable.

## What you need to do

**Use the monorepo for Sdui Meet and vault-proxy**
- *Who:* anyone who changes or builds Sdui Meet (Sdui's video calls, built on the open-source Jitsi Meet) or
  vault-proxy (the service in front of the secret store used for 2FA).
- *What:* vault-proxy moved from `sdui-hq/sduiapp-vault-proxy` to `apps/vault-proxy` on 2026-11-02; production
  runs the monorepo build since 2026-11-03 ([#1653](https://github.com/7education/sdui-monorepo/pull/1653)). Sdui Meet
  moved to `apps/sduiapp-meet` on 2026-11-20; the old repo `sdui-hq/sduiapp-meet` is read-only
  ([#1785](https://github.com/7education/sdui-monorepo/pull/1785)). (`sdui-hq` is Sdui's GitHub organisation from before
  7education.) New rule: merge a PR that updates Jitsi with a merge commit, never squash or rebase, or the next
  update breaks.
- *Help:* the Teams channel "sdui".

**Check your calls to the Sdui API**
- *Who:* teams whose own apps or services call Core's `/v1` API.
- *What:* three changes, all in production on the day they merged:
  - *Step-up* is the extra login check with the second factor before sensitive pages such as the classbook and
    sick notes. Since 2026-11-06 users are asked about once a day instead of every 6 hours, and enter only the
    second factor instead of logging in again. It used to skip users without e-mail 2FA; now their requests can get
    `401 step_up_required` too. Service tokens (Passport clients) are not affected. In the app, sick notes now ask
    for step-up and the exports list no longer does ([#1688](https://github.com/7education/sdui-monorepo/pull/1688)).
  - Chat translation (`GET /v1/channels/chats/{chat}/messages/{message}/translate`) returns `422` for schools that
    switch on on-device translation: read it as "this school translates in the app, not on the server". The
    switch is off for every school today ([#1790](https://github.com/7education/sdui-monorepo/pull/1790),
    2026-11-26).
  - `GET /v1/find-schools`, the school search before login, no longer lists the new `holder` schools (see Coming
    up). No action unless you need them ([#1747](https://github.com/7education/sdui-monorepo/pull/1747), 2026-11-12).
- *Help:* the Teams channel "sdui", or mention `@7education/sdui` on a PR.

**If you read the Classes & Groups service**
- *Who:* teams that read school years, classes, courses and enrollments from this separate service, which Core fills.
- *What:* since 2026-11-11 Core no longer sends school years that start before 2025-01-01 (so 2024/25 and older), or
  their classes, courses and enrollments ([#1684](https://github.com/7education/sdui-monorepo/pull/1684),
  [#1685](https://github.com/7education/sdui-monorepo/pull/1685)). The PRs don't say what happens to data already sent.

Nothing else needs action from you.

## Where this is going

**Progress:** 2 repos moved into the monorepo this month (vault-proxy, Sdui Meet); 1 is waiting (Untis). Code
from the repos in `sdui-hq` moves into one repo: one place to search, one PR flow, one CI.

**AI that stays closer to the user.** Chat translation can now run on the user's device with open models instead of
DeepL or Microsoft: the text stays on the device and costs nothing per message. Schools switch it on one by one
([#1790](https://github.com/7education/sdui-monorepo/pull/1790)). The Seven Assistant, the AI helper in the app, can
search a user's own chats where schools switch it on ([#1418](https://github.com/7education/sdui-monorepo/pull/1418),
[#1801](https://github.com/7education/sdui-monorepo/pull/1801)).

## Good to know

- **Merged usually means live the same day.** Deploys are started by hand from `main` almost every workday and ship
  everything merged since the last one; this month's main changes went live within an hour of their merge.
- **The `pipeline / …` checks on your PR are a trial** of the platform team's shared delivery pipeline, on its own
  runners since 2026-11-18. They deploy nothing and don't block a merge; their red Core integration checks are the
  pipeline's fault for now ([#1773](https://github.com/7education/sdui-monorepo/pull/1773), [#1788](https://github.com/7education/sdui-monorepo/pull/1788)).
- **Sdui production alerts now run in Coralogix**, the monitoring tool: since 2026-11-16, 84 alerts on errors, response
  times, queues, encryption and the servers post to Slack `#coralogix-notifications`. The *Sdui* dashboard folder there
  holds the production health and logins dashboard ([change](https://github.com/7education/Infrastructure/commit/6389568),
  [Infrastructure#84](https://github.com/7education/Infrastructure/pull/84)).
- **App fixes:** encrypted push on iOS ([#1661](https://github.com/7education/sdui-monorepo/pull/1661)), the Android chat input above the keyboard ([#1739](https://github.com/7education/sdui-monorepo/pull/1739), [#1782](https://github.com/7education/sdui-monorepo/pull/1782)), faster
  unread counts ([#1791](https://github.com/7education/sdui-monorepo/pull/1791), [#1802](https://github.com/7education/sdui-monorepo/pull/1802)).
